138–145 minutos · sin forzar ejemplo

2FN: no inventemos claves compuestas

La 2FN importa sobre todo cuando la clave primaria tiene varias partes. Nuestro recorte usa linea_id, así que no cambiaremos el modelo solo para fabricar un ejemplo.

Principio: si una clave fuera (pedido_id, plato_id), ningún atributo no clave debería depender solo de pedido_id o solo de plato_id.

2FNPrincipio, no artificio
145–154 minutos · dependencia transitiva

3FN: no copies atributos de otra entidad

Error

pedido guarda mesa_id y también puestos.

Pero puestos depende de mesa_id.

Corrección

puestos vive una sola vez en mesa.

El pedido solo conserva la relación con la mesa si la necesita.

Señal de buen diseño: cambiar la capacidad de una mesa no exige editar decenas de pedidos.
3FNEvitar copias que se contradicen
154–162 minutos · reconstrucción

pedido.total: ¿guardar o reconstruir?

pedido.total = 102000

Puede quedar viejo si cambian las líneas.

SUM(cantidad * precio_unitario)

Puede reconstruirse desde linea_pedido.

No es ley universal: si el total tiene valor legal, impuestos, redondeos o cierre contable, podría guardarse como hecho histórico.

162–170 minutos · SQL conocido

Si quitas una copia, debes poder recuperarla

WITH totales AS (
    SELECT pedido_id,
           SUM(cantidad * precio_unitario) AS total
    FROM linea_pedido
    GROUP BY pedido_id
)
SELECT p.pedido_id, t.total
FROM pedido p
JOIN totales t ON t.pedido_id = p.pedido_id;
No basta con que ejecute: revisa que no multiplique filas y que cada pedido conserve su total esperado.
