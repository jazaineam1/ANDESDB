2FN · provocar anomalía

Cambia el nombre en una sola copia

UPDATE lab_2fn_linea_mal
SET nombre_plato = 'Ajiaco santafereño'
WHERE pedido_id = 1
  AND plato_id = 10;
El mismo plato_id = 10 puede quedar con dos nombres.
2FN · anomalía de actualizaciónLa duplicación se contradice
2FN · detectar

Haz que la base muestre la contradicción

SELECT plato_id,
       COUNT(DISTINCT nombre_plato) AS nombres_distintos
FROM lab_2fn_linea_mal
GROUP BY plato_id
HAVING COUNT(DISTINCT nombre_plato) > 1;
Si aparece 10: tenemos evidencia de inconsistencia. La dependencia viene de la regla “un plato_id identifica un plato”.

2FN · reconstruir

Separar no significa perder información

SELECT l.pedido_id,
       p.nombre_plato,
       l.cantidad
FROM lab_2fn_linea_bien l
JOIN lab_2fn_plato_bien p
  ON p.plato_id = l.plato_id
WHERE l.plato_id = 10;
Todas las filas muestran un único nombre del plato porque ese nombre vive una sola vez.

3FN · el rodeo

Mira la cadena, no solo la tabla

pedido_id→mesa_id→puestos

pedido_id determina

qué mesa usa el pedido.

mesa_id determina

cuántos puestos tiene esa mesa.

Supuesto de negocio del ejercicio: puestos es la capacidad actual propia de MESA; no un dato histórico congelado del pedido.
3FN · dependencia transitivapedido → mesa → puestos
3FN · provocar anomalía

La mesa cambia, pero actualizamos solo una copia

UPDATE lab_3fn_pedido_mal
SET puestos = 6
WHERE pedido_id = 4;
Ahora mesa_id = 1 puede aparecer con 4 y con 6 puestos.
3FN · anomalíaEl dato pertenecía a MESA
3FN · detectar

La misma técnica vuelve a funcionar

SELECT mesa_id,
       COUNT(DISTINCT puestos) AS capacidades_distintas
FROM lab_3fn_pedido_mal
GROUP BY mesa_id
HAVING COUNT(DISTINCT puestos) > 1;
La consulta descubre el síntoma. La regla de negocio dice que una mesa tiene una capacidad actual.
3FN · evidenciaMisma herramienta, otra dependencia
3FN · después

Un UPDATE en MESA cambia la capacidad que todos los pedidos consultan.

3FN · comprobar

Reconstruye con JOIN

SELECT p.pedido_id,

Crear LINEA_PEDIDO

CHECKPOINT 3: ahora las flechas del modelo son reglas

CREATE TABLE linea_pedido (
  linea_id BIGINT GENERATED ALWAYS AS IDENTITY,
  pedido_id BIGINT NOT NULL,
  plato_id BIGINT NOT NULL,
  cantidad INTEGER NOT NULL,
  precio_unitario NUMERIC(10,2) NOT NULL,

  CONSTRAINT pk_linea_pedido PRIMARY KEY (linea_id),
  CONSTRAINT fk_linea_pedido_pedido
    FOREIGN KEY (pedido_id) REFERENCES pedido(pedido_id),
  CONSTRAINT fk_linea_pedido_plato
    FOREIGN KEY (plato_id) REFERENCES plato(plato_id),
  CONSTRAINT ck_linea_cantidad CHECK (cantidad > 0)
);
