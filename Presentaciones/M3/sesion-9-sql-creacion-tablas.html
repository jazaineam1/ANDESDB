Dónde vamos a escribir todo esto

Todo lo que viene — CREATE, INSERT, UPDATE, DELETE, DROP y ALTER — necesita un PostgreSQL de verdad. El nuestro es Supabase: se abre en el navegador, no se instala nada.

  1. Entren a supabase.com/dashboard y creen la cuenta con su correo.
  2. Van a caer en la pantalla de proyectos.
  3. Arriba a la derecha, New project.

Por hoy es solo un motor

Supabase trae autenticación, almacenamiento y APIs. Nada de eso hoy: hoy es un PostgreSQL con una ventana para escribir SQL.

Crea el proyecto, y guarda la contraseña

  1. Project name: algo que reconozcan, por ejemplo andesdb-s9.
  2. Database password: una contraseña larga. Guárdenla antes de seguir.
  3. Region: la más cercana.
  4. Create new project, y esperen a que termine de aprovisionar.

Ojo con la palabra «clave»

La database password no es una clave primaria ni una clave foránea. Es la contraseña del servidor: se guarda, no se comparte y no se pega en el chat.

El SQL Editor: aquí ocurre la clase entera

  1. Menú izquierdo → SQL Editor.
  2. New query, o el +.
  3. Escriban ahí el SQL de las láminas que siguen.
  4. Run, o Ctrl+Enter.

Se ejecuta lo que esté seleccionado

Si hay varias instrucciones y no seleccionan ninguna, se ejecutan todas. Para correr una sola, sélecciona esa y pulsa Run.

Success. No rows returned está bien

CREATE, UPDATE, DELETE y ALTER cambian la estructura o los datos: no tienen por qué devolver filas. Para verlas, añadan RETURNING * o consulten con SELECT.

Table Editor: comprobar que quedó

Después de cada CREATE o INSERT, vayan a verlo. Es la forma de saber que el SQL hizo lo que creían que hacía.

  1. Menú izquierdo → Table Editor.
  2. Arriba, el selector de schema: dejen public.
  3. La tabla nueva aparece en la lista de la izquierda.
  4. Al abrirla se ven las columnas, sus tipos y las filas insertadas.

Y si no aparece

Recarguen la página. Si sigue sin estar, el CREATE dio error: vuelvan al SQL Editor y lean el mensaje rojo, que dice exactamente qué línea no le gustó.

Dos cosas se llaman «clave», y no se parecen

Claves de la base — las de esta clase

PRIMARY KEY identifica una fila. FOREIGN KEY apunta a la clave primaria de otra tabla. Son diseño: se escriben en el CREATE TABLE, viven dentro de la tabla y cualquiera puede verlas.

Claves de acceso — las de la plataforma

La publishable (antes anon) puede viajar en un navegador. La secret (antes service_role) se salta todas las reglas de seguridad, y la database password abre el servidor entero.

Regla para hoy

Lo que se comparte en el chat de la clase: la Project URL y, si hace falta, la clave publishable.

Lo que no se comparte nunca: la database password, la clave secret y la cadena de conexión directa a Postgres.

Y por qué importa aquí

Porque en las láminas que siguen la palabra clave aparece todo el rato —PRIMARY KEY, FOREIGN KEY, REFERENCES— y no tiene nada que ver con entrar a ningún sitio. Es el nombre de una columna que sirve para identificar y para enlazar.
