Tu primera base de documentos en MongoDB Atlas

No reemplaza Firestore: es la comparación del mismo caso en el otro motor de documentos. Extensión opcional, después de terminar tu práctica en Firebase.

Qué es esto, y qué no es

Atlas App Services y su Data API llegaron a su fin de soporte (EOL) en 2025: hoy no existe una forma soportada de que una página estática hable con Atlas sin backend propio. Por eso el carrito en vivo de la clase usa Firebase, y Atlas conserva un solo rol en esta sesión: la práctica del Data Explorer, igual que cuando escribes documentos a mano en Firestore.

Por qué esta guía no tiene capturas de pantalla

La guía de Firebase sí las tiene porque se verificaron en vivo, clic a clic, contra la consola real. Esta guía en cambio se redactó verificando cada etiqueta contra la documentación oficial vigente de MongoDB Atlas el 2026‑09‑09 — sin capturas que queden desactualizadas la próxima vez que Atlas rediseñe un formulario. Si un botón no dice exactamente esto, la interfaz cambió después de esa fecha: sigue el propósito del paso, no el texto literal.

Hazlo conmigo: ruta completa de estudiante

Tu meta es tener, dentro de un clúster gratuito M0 propio, una colección platos con al menos dos documentos que no compartan exactamente los mismos campos — la misma comparación que ya hiciste en Firestore.

1 Crea tu cuenta y tu proyecto

  1. Ve a cloud.mongodb.com y crea una cuenta (o inicia sesión) con tu correo.
  2. Si es tu primera vez, Atlas te ubica dentro de una organización y un proyecto por defecto; si no, en el menú Projects pulsa New Project, dale un nombre reconocible (por ejemplo restaurante-abc-tu-nombre) y continúa.
Debes ver: el panel Project Overview de tu proyecto, vacío, con un botón para crear un clúster.

2 Despliega el clúster gratuito M0

  1. En Project Overview, pulsa Create.
  2. Elige la opción M0 (gratis, para aprender — no la confundas con un tier pago).
  3. Elige un proveedor (AWS, GCP o Azure) y una región cercana; solo aparecen las que ofrecen M0.
  4. En Name escribe un nombre corto; no podrás cambiarlo después de crear el clúster.
  5. Pulsa Create.
Debes ver: se abre el asistente Security Quickstart — el clúster queda listo en menos de un minuto, pero primero completa el paso 3.

3 Security Quickstart: usuario y acceso de red

  1. En How would you like to authenticate your connection? deja Username and Password, escribe un usuario y una contraseña (o usa la que Atlas sugiere) y pulsa Create Database User.
  2. En Where would you like to connect from? pulsa Add My Current IP Address.
  3. Pulsa Finish and Close y luego Go to Overview.
Debes ver: tu clúster en estado activo (ya no Creating) en el Project Overview.
Nota: esta contraseña es solo para tu clúster de práctica; no la reutilices en nada real, y no la pegues en el chat de clase.

4 Entra al Data Explorer

  1. En el menú lateral, dentro de la sección Database, pulsa Data Explorer.
  2. Si Atlas te lo pide, confirma la conexión con el usuario que creaste en el paso 3.
Debes ver: un panel vacío (todavía no hay bases de datos) con una opción para crear la primera.

5 Crea la base de datos y la colección

  1. Pulsa el botón para crear tu primera base de datos.
  2. En Database name escribe restaurante_abc.
  3. En Collection name escribe platos.
  4. Confirma con Create Database (para colecciones adicionales más tarde, el botón equivalente es Create Collection, junto al nombre de la base al pasar el cursor sobre ella).
Debes ver: la ruta restaurante_abc → platos, vacía, en el panel izquierdo del Data Explorer.

6 Inserta dos documentos que no compartan todos los campos

  1. Con platos seleccionada, pulsa el menú desplegable Add Data y elige Insert Document.
  2. Verás tres modos, con íconos para alternar entre ellos: Shell Syntax (por defecto), Field-by-Field y JSON Mode. Usa JSON Mode: es el más parecido a lo que ya escribiste en Firestore.
  3. Pega el primer documento de la tabla de abajo y pulsa Insert.
  4. Repite Add Data → Insert Document con el segundo documento.
{ "plato_id": 1, "nombre": "Ajiaco santafereño", "precio_actual": 28000,
  "categoria": "fuerte", "alergenos": ["gluten", "lácteos"], "foto": "ajiaco.jpg" }
{ "plato_id": 8, "nombre": "Tamal tolimense", "precio_actual": 22000,
  "categoria": "fuerte", "alergenos": ["gluten"],
  "disponible_desde": "06:00", "disponible_hasta": "11:00" }
Debes ver: 2 documentos en platos; Atlas les asigna un _id propio (un ObjectId) además de tu plato_id — igual que Firestore con su ID automático.
Si el botón Insert no responde: revisa que el JSON tenga comillas dobles en todas las claves y que no falte ni sobre una coma; el modo JSON no acepta la sintaxis relajada del modo Shell.

7 Compara con Firestore

  1. Abre el mismo par de platos en tu colección carta de Firestore.
  2. Anota: mismos campos, mismos valores, dos motores distintos, dos consolas distintas.

La conclusión que debes poder explicar

Firestore y Atlas resuelven el mismo problema — documentos con campos variables, sin JOIN — con consolas y límites distintos. La diferencia que sí importa para esta clase no es cuál base de documentos es «mejor»: es que Atlas ya no ofrece una ruta soportada para que el navegador le hable directo, y Firestore sí.

Evidencia de cierre

Muestra estas dos capturas propias

  1. Tu clúster M0 activo, con el nombre que le pusiste.
  2. restaurante_abc → platos con los 2 documentos, mostrando el campo que Tamal tiene y Ajiaco no.

Cuando termines

Este clúster es tuyo, no el de la clase: bórralo cuando quieras (Project Overview → ⋯ → Terminate) sin afectar nada del carrito compartido ni de la sesión.
