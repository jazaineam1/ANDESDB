Concepto 1

Particionar sirve para poder omitir particiones completas

Una tabla particionada se divide en segmentos. Si el filtro usa correctamente la columna de partición, BigQuery puede ignorar las particiones que no pueden aportar filas: eso es partition pruning.

No es “fecha = partición”. El patrón de consulta manda

Concepto 2

Clusterización organiza bloques según columnas de acceso frecuente

BigQuery organiza los datos de una tabla clustered usando una o varias columnas. Cuando filtras por esas columnas, puede usar la información de clustering para evitar bloques que no contienen datos relevantes.

Partición

Descarta particiones completas. Es una segmentación de mayor escala.

Clustering

Ayuda a podar bloques según columnas de filtro o agregación frecuentes.

No confundas: clustering no es “para texto”. La decisión depende del patrón de acceso y BigQuery admite múltiples tipos de dato como columnas de clustering.
ClusterizaciónBlock pruning
El orden sí importa

La primera columna refleja el patrón dominante

CREATE OR REPLACE TABLE curso.ventas_optimizadas
PARTITION BY fecha
CLUSTER BY categoria, cliente_id

Precisión técnica

Partición y clustering no tienen la misma rigidez

Partición

Una tabla no particionada no se convierte directamente en particionada. Para cambiar esa estrategia normalmente creas una nueva tabla particionada y copias/seleccionas los datos.

Clustering

BigQuery sí permite modificar o retirar la especificación de clustering de una tabla existente; los datos pueden necesitar reclustering para reflejar completamente la nueva organización.

Evita enseñar “las dos decisiones son inmutables después de crear la tabla”: esa frase es incorrecta para clustering.
PrecisiónPartición ≠ clustering
