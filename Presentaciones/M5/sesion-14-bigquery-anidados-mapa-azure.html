Normalizar y anidar no son doctrinas opuestas

Operación

Si una línea se crea, modifica o valida por separado, una tabla independiente protege reglas y evita redundancia operacional.

Analítica

Si casi siempre analizas el pedido con todas sus líneas, anidar puede acercar la forma del dato a la consulta y evitar JOINs repetidos.

Regla mental: primero pregunta cómo se lee y cómo cambia el dato; después decide si separar o anidar.

STRUCT agrupa campos; ARRAY conserva varios valores

SELECT STRUCT(
  42 AS pedido_id,
  [STRUCT('Ajiaco' AS plato, 2 AS cantidad),
   STRUCT('Jugo'   AS plato, 1 AS cantidad)] AS lineas
) AS pedido;

STRUCT

Un contenedor con campos nombrados que pueden tener tipos distintos.

ARRAY

Una colección ordenada de elementos del mismo tipo; puede ser un ARRAY<STRUCT<...>>.

Predice: ¿cuántas filas devuelve la consulta? ¿Cuántas líneas existen dentro de esa fila?
BigQueryJerarquía dentro de la fila
30–42 min · hazlo conmigo

UNNEST cambia el grano: convierte un arreglo en filas

WITH pedidos AS (
  SELECT 42 AS pedido_id,
    [STRUCT('Ajiaco' AS plato,2 AS cantidad),
     STRUCT('Jugo' AS plato,1 AS cantidad)] AS lineas
)
SELECT pedido_id, l.plato, l.cantidad
FROM pedidos, UNNEST(lineas) AS l;

Antes

Una fila = un pedido que contiene un arreglo.

Después

Una fila = una línea perteneciente al pedido.

Antes de ejecutar: ¿esperas 1 fila, 2 filas o más? Justifica con el grano.
UNNESTEl grano vuelve a mandar

El peligro conocido: multiplicar filas sin querer

Si una fila tiene dos arreglos independientes y expandes ambos, puedes producir combinaciones entre sus elementos.

Ejemplo

3 líneas × 2 promociones pueden producir hasta 6 combinaciones si ambos arreglos se expanden sin controlar la relación.

La pregunta correcta

Después de cada UNNEST, vuelve a declarar: “una fila representa…”

CSV, JSON y Parquet no dicen lo mismo sobre la forma del dato

CSV

Plano y simple. Excelente para intercambio tabular; la jerarquía debe aplanarse.

JSON / JSONL

Semiestructurado. Conserva objetos y arreglos de forma natural y es habitual en APIs/eventos.

Parquet

Columnar y tipado. Orientado a lectura analítica eficiente y capaz de conservar estructuras anidadas.

Elige uno para: intercambio humano simple · documento/API · analítica columnar.

¿Qué hizo realmente BigQuery?

ARRAY

Permitió varios elementos asociados a una misma fila.

STRUCT

Agrupó campos relacionados sin convertirlos en columnas independientes al mismo nivel.

UNNEST

Expandió una colección y cambió explícitamente el grano del resultado.

Mini reto: si un pedido tiene 4 líneas, ¿cuántas filas esperas después de UNNEST(lineas)? ¿Qué representa cada una?

La sesión cabe en cuatro decisiones

  • ARRAY: varios elementos permanecen asociados a una fila.
  • STRUCT: varios campos relacionados permanecen agrupados.
  • UNNEST: expandir un arreglo cambia el grano; debes poder decir qué representa cada fila.
  • Formato/servicio: JSON, Parquet, Blob o Cosmos se eligen por uso, no por moda.
