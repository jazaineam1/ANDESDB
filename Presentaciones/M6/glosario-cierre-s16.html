1 · Esqueleto de una consulta

Orden de escritura

SELECT columnas FROM tabla WHERE condición GROUP BY columnas HAVING condición sobre agregados ORDER BY columnas LIMIT n;

Orden lógico del motor

FROM → WHERE → GROUP BY → agregación → HAVING → SELECT → ORDER BY → LIMIT

Idea clave: WHERE actúa antes de calcular agregados; HAVING filtra grupos después.

2 · Consultar, filtrar y resumir

4 · Construir por etapas

WITH / CTE

Divide un problema complejo en tablas intermedias legibles.

WITH resumen AS ( SELECT id, SUM(valor) total FROM detalle GROUP BY id ) SELECT * FROM resumen;

CASE

Convierte condiciones en categorías o indicadores.

CASE WHEN total > 100 THEN 'alto' ELSE 'normal' END

COALESCE

Usa el primer valor no nulo.

COALESCE(descuento,0)

COUNT(DISTINCT x) cuenta valores únicos.

Antes de ejecutar: pregunta → grano esperado → tablas → llaves → JOIN → filtros → agregación → validación.
Error clásico: si un JOIN 1:N multiplica filas, un total puede inflarse. Compara conteos antes/después y agrega al grano correcto antes de unir.

5 · De reglas a modelo

regla de negocio → entidad → atributo → relación → cardinalidad → clave → tabla → restricción

Entidad / atributo

Entidad = cosa con identidad propia. Atributo = dato que describe esa entidad.

PK / FK

PK identifica una fila. FK referencia otra entidad y protege la relación.

Cardinalidad

1:1 · 1:N · N:N. Una N:N normalmente requiere una tabla puente.

6 · Normalización

FormaIdea prácticaPregunta útil
1FNValores atómicos; no listas repetidas dentro de una celda.¿Cada campo contiene un valor del dominio esperado?
2FNEn clave compuesta, los atributos dependen de la clave completa.¿Algo depende solo de una parte de la clave?
3FNLos atributos no clave dependen de la clave, no de otro atributo no clave.¿Estoy guardando información de otra entidad?
Objetivo: reducir redundancia, anomalías de inserción/actualización/borrado y mantener una reconstrucción coherente mediante relaciones.

DDL · estructura

9 · Documentos y CAP

Embeber

Conviene cuando los datos se leen juntos, tienen ciclo de vida cercano y el agregado no crece sin control.

Referenciar

Conviene cuando una entidad se comparte, cambia por separado o crecería/repetiría demasiado.

CAP ayuda a razonar sobre consistencia, disponibilidad y tolerancia a particiones de red en sistemas distribuidos. No significa “elige dos productos”.

14 · Checklist antes de confiar en un resultado

  • ¿Qué representa una fila antes de consultar?
  • ¿Qué representa una fila después del JOIN/UNNEST?
  • ¿La llave de unión corresponde a la relación real?
  • ¿Aumentó inesperadamente el número de filas?
  • ¿Estoy filtrando filas con WHERE o grupos con HAVING?
  • ¿Hay NULL relevantes?
  • ¿COUNT(*) y COUNT(DISTINCT id) cuentan lo mismo?
  • ¿Un estado observado es realmente el último estado?
  • ¿La tabla física coincide con el patrón de consultas?
  • ¿Puedo explicar el resultado sin mirar el código?
Idea final: problema → evidencia → grano → modelo → integridad → representación → almacenamiento → analítica → validación → decisión.
