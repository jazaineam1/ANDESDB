Herramienta 1 · SQL y grano

Una query puede ejecutar y aun así responder otra pregunta

Tiempo

“Máximo” y “último” no son sinónimos. Si importa el orden, debes modelar el orden.

JOIN 1:N

Después del JOIN, una entidad puede aparecer varias veces. COUNT(*) cuenta filas resultantes.

Promedios

Antes de promediar, vuelve al grano correcto para que una entidad con más registros no pese más por accidente.

Antes de calcular, termina esta frase: “una fila representa…”

Consultar bien depende de representar bien

Entidades y relaciones

Busca identidad propia, cardinalidad y el lugar donde debe vivir cada clave.

Normalización

Separa atributos cuando una dependencia hace que el mismo hecho se repita en muchas filas.

Herramientas 3 y 4

Una base no solo guarda: también impide errores y representa acceso

DDL Mutation

El starter trae columnas, no restricciones. PK, FK, NOT NULL y CHECK deben demostrarse con ataques; la evolución de dominios se trata como migración, no como ausencia de validación.

Document Lab

Distingue embeber, guardar una referencia dentro y mantener el recurso fuera. Además decide SQL/NoSQL y una partition key de Cosmos desde el patrón de acceso.

Diseñar una regla incluye diseñar el contraejemplo que debería romperla.
S9–S11integridad + patrón de acceso

OLTP→ingesta→transformación→hecho→dimensiones→OLAP

Grano

Antes de escoger medidas debes escribir qué representa exactamente una fila de la tabla de hechos.

Consumo histórico

Herramienta 6 · Diseño físico

En BigQuery la pregunta es: ¿qué partes puedo evitar leer?

Partición

El Workbench muestra frecuencias reales del workload para derivar la partición y el orden del clustering.

Clustering

El orden del clustering se deriva de qué filtros aparecen primero en el workload, no de una regla simplista sobre cardinalidad.

Pruning

La decisión se comprueba por cuánto reduce la lectura candidata, no porque una columna “parezca importante”.

No memorices una columna concreta: identifica el patrón de consulta.

Herramienta 7 · Anidados + transferencia cloud

ARRAY/STRUCT se entienden por el grano; Azure por la necesidad

ARRAY / STRUCT / UNNEST

Antes y después de expandir una colección, declara qué representa una fila. Dos colecciones independientes pueden multiplicar filas. La consulta de UNNEST se ejecuta localmente con DuckDB-Wasm y acepta alias equivalentes.

Transferencia Azure

No traduzcas “producto A = producto B”. Primero clasifica la necesidad: almacenar objetos, operar documentos, procesar analítica o consumir BI.

Importante: aquí no mostramos el mapeo exacto del Boss. Debes decidirlo a partir de almacenamiento, patrón de acceso, procesamiento y consumo.
