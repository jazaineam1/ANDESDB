Diseño de bases de datos

Pasaste de una conversación de negocio a un modelo defendible

regla→entidad→atributo→relación→cardinalidad

Identidad

PK identifica una fila. Una clave no es “porque sí”: representa identidad estable.

Relaciones

FK conecta entidades y protege referencias. 1:1, 1:N y N:N cambian el diseño.

Dependencias

Separar atributos por dependencia reduce redundancia y anomalías.

reglas → ER → claves → cardinalidad → 1FN/2FN/3FN → esquema implementable

Dominio 2 · familia Azure SQL

La pregunta correcta es: ¿cuánto control y compatibilidad necesitas?

Azure SQL Database

PaaS de base de datos SQL administrada.

CUANDO: aplicación nueva / mínimo manejo de infraestructura.

Azure SQL Managed Instance

PaaS con mayor compatibilidad de instancia SQL Server.

CUANDO: migración necesita características de instancia.

SQL Server on Azure VM

IaaS: control sobre VM, SO y SQL Server.

CUANDO: necesitas control de infraestructura.

Azure Database for PostgreSQL

PostgreSQL administrado en Azure.

CUANDO: el motor requerido es PostgreSQL.
Atajo mental: más administración Azure → PaaS; más control tuyo → VM/IaaS.

Dominio 3 · Non-relational data

Storage y base NoSQL no son lo mismo

Blob Storage

objetos: imágenes, video, backups, archivos de datos.

PIENSA: object storage.

Azure Files

file shares administrados accesibles mediante protocolos de archivos.

PIENSA: carpeta compartida.

Table Storage

store NoSQL simple de clave/atributo.

PIENSA: key/attribute sencillo.

Cosmos DB

base NoSQL distribuida para aplicaciones que requieren características de base de datos.

PIENSA: datos NoSQL operacionales.
Un archivo JSON puede vivir en Blob. Que un dato sea JSON no basta para decidir Cosmos DB.
Dominio 3storage ≠ database
Dominio 3 · Azure Cosmos DB

DP-900 pide reconocer casos de uso y APIs de Cosmos DB

Cuándo aparece Cosmos DB

aplicaciones NoSQL distribuidas, escala, baja latencia y patrones de acceso no relacionales.

La decisión sigue comenzando por el patrón de acceso.

Qué significa “API” aquí

la interfaz/modelo con el que la aplicación interactúa con Cosmos DB. En DP-900 debes reconocer que existen distintas APIs y que no todas las cargas se modelan igual.

Evita el atajo: documento flexible → “automáticamente Cosmos”. Primero pregunta por el store y por las necesidades de la aplicación.
