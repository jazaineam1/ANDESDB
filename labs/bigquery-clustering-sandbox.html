Clustering en BigQuery Sandbox

Este laboratorio no depende de un enlace interno de Google Skills. Usa BigQuery Sandbox y datos públicos. El objetivo es comparar una tabla sin clustering con la misma tabla organizada por una columna de acceso frecuente.

Abrir BigQuery StudioGuía oficial Sandbox

0 · Antes de empezar

BigQuery Sandbox funciona sin tarjeta de crédito ni cuenta de facturación y permite consultar datasets públicos. Google aplica límites gratuitos de uso. Si ya tienes un proyecto con facturación, revisa siempre el proyecto activo antes de ejecutar.

Importante: clustering suele mostrar beneficios más visibles cuando la tabla o partición supera aproximadamente 64 MB. Si la diferencia en bytes es pequeña, eso también es un resultado válido: explica por qué el tamaño importa.

1 · Comprueba que BigQuery responde

SELECT 1 AS listo;

Si devuelve 1, continúa.

2 · Crea un dataset de trabajo

CREATE SCHEMA IF NOT EXISTS s13_bigquery
OPTIONS(location = 'US');

El dataset queda en tu proyecto actual. No necesitas escribir manualmente el Project ID.

3 · Crea una tabla base sin clustering

Usaremos preguntas de Stack Overflow de 2024. Conservamos pocas columnas para no almacenar información innecesaria.

CREATE OR REPLACE TABLE s13_bigquery.posts_base AS
SELECT
  id,
  owner_user_id,
  creation_date,
  score
FROM `bigquery-public-data.stackoverflow.posts_questions`
WHERE creation_date >= TIMESTAMP('2024-01-01')
  AND creation_date <  TIMESTAMP('2025-01-01');

4 · Crea la misma tabla con clustering

CREATE OR REPLACE TABLE s13_bigquery.posts_clustered
CLUSTER BY owner_user_id AS
SELECT *
FROM s13_bigquery.posts_base;

Ahora ambas tablas contienen las mismas filas. La diferencia es la organización física de los bloques.

5 · Predice antes de ejecutar

Consulta A

Tabla base, sin clustering.

Consulta B

Tabla clusterizada por owner_user_id.

Escribe primero tu hipótesis: “Espero que la tabla clusterizada lea menos porque…”

6 · Ejecuta la consulta sobre la tabla base

SELECT
  COUNT(*) AS preguntas,
  AVG(score) AS score_promedio
FROM s13_bigquery.posts_base
WHERE owner_user_id BETWEEN 10000 AND 20000;

Abre Execution details / Job details y registra los bytes procesados.

7 · Ejecuta exactamente el mismo filtro sobre la tabla clusterizada

SELECT
  COUNT(*) AS preguntas,
  AVG(score) AS score_promedio
FROM s13_bigquery.posts_clustered
WHERE owner_user_id BETWEEN 10000 AND 20000;

Compara los bytes procesados y los detalles de ejecución con la consulta anterior.

8 · Cambia el filtro para probar el límite del diseño

Ahora consulta una columna que no es la columna de clustering:

SELECT COUNT(*) AS preguntas
FROM s13_bigquery.posts_clustered
WHERE score >= 20;

Pregunta: ¿esperas el mismo beneficio? ¿Por qué?

9 · Cierre

Completa estas dos frases:

  1. Clustering ayudó más cuando…
  2. Clustering no garantiza menor lectura cuando…
Idea esperada: BigQuery puede hacer block pruning cuando los filtros aprovechan las columnas de clustering. El efecto depende del patrón de consulta y del tamaño/organización de los bloques.
