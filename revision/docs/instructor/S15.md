# S15 · Guía docente

## Pregunta central
¿Puedo resolver un caso nuevo sin receta, decidir qué representación necesito y demostrar que mi solución es confiable?

## Hilo conductor
- **Hereda:** S1–S14 construyeron un repertorio: preguntar, controlar grano, levantar reglas, modelar, implementar, elegir representación, analizar y validar.
- **Pregunta de hoy:** ¿puedo usar ese repertorio cuando el enunciado no me entrega tecnología, modelo ni consulta?
- **Evidencia de salida:** cuatro grupos de evidencia defendibles: decisión/modelo, base que protege, respuesta comprobada y transferencia.
- **Puente:** S16 usa los aciertos y errores reales de este reto para diagnosticar concepto, transferencia a Azure y lectura de escenarios.

## Error esperable principal
Empezar por `CREATE TABLE`, copiar la arquitectura del Restaurante ABC o elegir tecnología por el formato del archivo antes de declarar el grano y la fuente de verdad.

## Dónde probablemente se atascan
- Al distinguir `casos.estado` como snapshot actual del historial de `eventos`.
- Al decidir si `evidencias.json` necesita realmente una representación documental o si están eligiendo NoSQL solo porque ven JSON.
- Al unir casos, eventos y evidencias y obtener multiplicación de filas sin reconocer el cambio de grano.
- Al convertir patrones de los datos en reglas del negocio que nadie confirmó.

## No avanzar hasta que…
El equipo supere las dos primeras puertas: haya escrito el grano de las tres fuentes, una pregunta de negocio, las reglas confirmadas frente a hipótesis y una decisión explícita sobre estado actual/historial y representación de evidencias.

## Evidencia mínima
Modelo coherente + DDL ejecutable + tres consultas con grano esperado + controles conocidos + una prueba negativa + una decisión tecnológica que el equipo pueda explicar y modificar.

## Si vas 15 minutos atrasado
Reduce la extensión analítica, no la validación. Conserva una consulta con JOIN, una agregación, una consulta temporal, un control de huérfanos y una prueba negativa. La arquitectura puede quedar como diagrama mínimo.

## Si vas 15 minutos adelantado
Cambia un requisito: evidencias compartidas entre casos, múltiples agentes por evento o eventos en tiempo real. Pide modificar una decisión, una parte del modelo y el control que debería reejecutarse; no rehagas todo el proyecto.

## Intervención docente
No entregues una arquitectura. Usa las cuatro puertas:
1. “¿Qué representa una fila/documento aquí?”
2. “¿Cuál es la fuente de verdad y por qué?”
3. “¿Qué regla protege esta PK/FK/CHECK?”
4. “¿Contra qué control demuestras que este resultado no se infló por el JOIN?”

Si aparece `DISTINCT`, pregunta primero qué relación multiplicó filas. Si el equipo usa IA o documentación, selecciona una línea al azar y pide explicación, cambio y revalidación.

## Regla de cierre
El proyecto está terminado cuando el equipo puede reproducir un resultado, mostrar una entrada inválida rechazada por su diseño, explicar una decisión de representación y decir qué validación repetiría después de un cambio.
