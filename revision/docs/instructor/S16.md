# S16 · Guía docente · cierre + preparación DP-900

## Propósito
S16 tiene dos trabajos distintos y ambos deben quedar visibles:

1. **Cerrar el diplomado con evidencia de progreso**, sin volver a evaluar lo que S15 ya integró.
2. **Dedicar la segunda mitad a una preparación inicial real de DP-900**, no solo a mostrar nombres Azure.

La transición docente es:

> Lo que ya sabes de datos no desaparece. Ahora vamos a usarlo para reconocer requisitos, servicios y distractores del ecosistema Microsoft.

## Principios
1. **S15 ya es la evaluación integradora.** S16 no crea otro examen custom.
2. **El repaso del curso no puede consumir la sesión.** Recupera conceptos solo para activar transferencia.
3. **DP-900 no es únicamente vocabulario.** El estudiante debe aprender a mapear requisito → concepto → servicio Azure.
4. **Fuente oficial vigente:** Study Guide en inglés, skills measured as of **July 21, 2026**.
5. **Una decisión cada 10–15 minutos.** Predicciones y microcasos sin nota.
6. **No recopilar portafolios, respuestas S1 ni mini encuesta.**
7. **La encuesta institucional ocurre después del cierre.**
8. **El temporizador de la presentación es el componente compartido de S15 v7**, no un timer local de S16.

## Blueprint oficial vigente
Microsoft Learn publica, para skills measured as of July 21, 2026:
- **Describe core data concepts: 25–30%**
- **Identify considerations for relational data on Azure: 20–25%**
- **Describe considerations for working with non-relational data on Azure: 15–20%**
- **Describe an analytics workload on Azure: 25–30%**

### Dominio 1 · Core data concepts
- structured / semi-structured / unstructured;
- formatos comunes y data stores;
- OLTP vs OLAP;
- responsabilidades de DBA, Data Engineer y Data Analyst.

### Dominio 2 · Relational data on Azure
Concentrarse en:
- Azure SQL Database;
- Azure SQL Managed Instance;
- SQL Server on Azure Virtual Machines;
- servicios Azure para motores open source, especialmente PostgreSQL.

Regla pedagógica:
> más administración por Azure → PaaS; más control del SO/instancia → VM/IaaS.

### Dominio 3 · Non-relational data
Distinguir:
- Blob Storage → objetos;
- Azure Files → file share;
- Table Storage → clave/atributo simple;
- Cosmos DB → base NoSQL distribuida.

El blueprint actual pide también casos de uso de Cosmos DB y reconocer que Cosmos DB expone distintas APIs. No enseñar “JSON = Cosmos DB”.

### Dominio 4 · Analytics
Debe incluir:
- ingesta y procesamiento;
- stores analíticos;
- Azure Databricks;
- Microsoft Fabric;
- batch vs streaming;
- servicios/capacidades Microsoft para real-time analytics;
- Power BI;
- modelos de datos en Power BI;
- visualización apropiada.

## Método para responder preguntas DP-900
1. **Clasifica el dominio.**
2. **Localiza la condición que manda.**
3. **Descarta opciones incompatibles.**
4. **Elige la opción que satisface el requisito diferencial.**
5. **Lee la explicación oficial y formula una regla transferible.**
