# S16 · Guía docente · cierre + preparación DP-900

## Propósito

La sesión final cumple dos funciones distintas y ambas deben quedar visibles:

1. **Cerrar el diplomado con evidencia de progresión**, sin volver a impartir S2–S15.
2. **Dedicar la segunda mitad a una preparación inicial real de DP-900**, usando el blueprint vigente y enseñando a mapear requisitos a servicios Azure.

La idea central es:

> El diplomado ya construyó la base conceptual. S16 la condensa y después la traduce al lenguaje y a las decisiones que aparecen en DP-900.

## Regla de tiempo

La S16 dura 180 minutos totales = **165 minutos útiles + 15 de pausa**.

### Primera parte · cierre del diplomado · 65 min

- **0–10 · Apertura + recorrido:** S2→S15 en una sola historia.
- **10–25 · SQL + pensamiento SQL:** repertorio, orden lógico, grano, JOIN y validación.
- **25–35 · Modelado + integridad:** reglas, entidades, cardinalidad, 1FN/2FN/3FN, PK/FK/CHECK.
- **35–45 · SQL/NoSQL:** patrón de acceso, documentos y elección por requisito.
- **45–55 · OLTP/OLAP + BigQuery + anidados:** recuperar solo las ideas transferibles.
- **55–65 · S15:** tres aprendizajes integradores. No repetir el Workbench ni resolver otro examen.

### 65–80 · Pausa · 15 min

Usa el temporizador compartido de S15 v7 (presentation-timer.js).

### Segunda parte · preparación DP-900 · 100 min

- **80–90 · Blueprint + transferencia:** pesos vigentes y mapa concepto→Azure.
- **90–105 · Dominio 1 · Core data concepts:** forma de datos, workloads y roles.
- **105–125 · Dominio 2 · Relational data on Azure:** familia Azure SQL + escenarios.
- **125–140 · Dominio 3 · Non-relational data on Azure:** Blob/Files/Table + Cosmos DB/APIs.
- **140–160 · Dominio 4 · Analytics:** Databricks, Fabric, batch/streaming, Power BI.
- **160–175 · Practice Assessment oficial:** seis preguntas razonadas, no carrera de respuestas.
- **175–180 · Voucher + plan + cierre:** qué hacer después y cómo usar el material del curso.

No proyectes minutaje por diapositiva; solo la pausa muestra tiempo.

## Cierre del diplomado · qué conservar

### SQL y pensamiento

**Lenguaje**
- SELECT, DISTINCT, WHERE, ORDER BY, LIMIT.
- GROUP BY, HAVING, agregaciones.
- INNER/LEFT/RIGHT/FULL JOIN.
- UNION / UNION ALL.
- WITH / CTE, CASE, COALESCE.
- INSERT, UPDATE, DELETE.
- CREATE/ALTER/DROP TABLE.

**Orden lógico**
- FROM → WHERE → GROUP BY → agregación → HAVING → SELECT → ORDER BY → LIMIT.

**Pensamiento**
- pregunta → grano → tablas → llaves → unión → filtros → agregación → validación.

### Modelado e integridad

- regla → entidad → atributo → relación → cardinalidad;
- 1:1, 1:N, N:N;
- 1FN, 2FN, 3FN;
- PK, FK, NOT NULL, UNIQUE, CHECK;
- una restricción se prueba por comportamiento.

### SQL/NoSQL y analítica

- elección por patrón de acceso;
- embeber vs referenciar;
- OLTP vs OLAP;
- grano, hechos, dimensiones y estrella;
- batch vs streaming;
- partición, clustering y pruning;
- ARRAY, STRUCT, UNNEST y formatos.

La recuperación termina aquí. S15 ya integró estos conceptos.

# Preparación DP-900

## 1 · Core data concepts

### Formas de datos
- estructurado;
- semiestructurado;
- no estructurado.

### Almacenamiento
- formatos comunes de archivos;
- bases de datos y otros almacenes;
- escoger un datastore por caso de uso.

### Workloads
- transaccional;
- analítico.

### Roles
- Database Administrator: opera/protege bases.
- Data Engineer: ingiere, transforma y construye pipelines.
- Data Analyst: modela para análisis, visualiza y comunica.

No presupongas que los estudiantes distinguen los tres roles solo por haber usado SQL.

## 2 · Relational data on Azure

El concepto relacional ya está trabajado. Lo nuevo es discriminar servicios.

### Azure SQL Database
PaaS de base de datos SQL administrada.

**Pista:** app moderna/nueva, no administrar SO.

### Azure SQL Managed Instance
PaaS con mayor compatibilidad a nivel de instancia SQL Server.

**Pista:** migración que requiere características de instancia sin administrar una VM.

### SQL Server on Azure Virtual Machines
IaaS con control de VM/SO/SQL Server.

**Pista:** el control del entorno es requisito.

### Azure Database for PostgreSQL
Motor PostgreSQL administrado.

**Pista:** el requerimiento explícito es PostgreSQL.

Secuencia docente:
**requisito → nivel de control → compatibilidad → servicio**.

## 3 · Non-relational data on Azure

### Blob Storage
Objetos: imágenes, video, backups, CSV, JSON, Parquet.

### Azure Files
File shares administrados.

### Table Storage
Clave/atributo NoSQL simple.

### Cosmos DB
Base distribuida y multimodelo.

DP-900 pide reconocer **casos de uso y APIs**. Usa como mínimo:
- API for NoSQL;
- MongoDB;
- Apache Cassandra;
- Apache Gremlin;
- Table.

No conviertas las APIs en un tema de programación: se reconocen para saber qué modelo/protocolo corresponde.

Fuente:
https://learn.microsoft.com/en-us/azure/cosmos-db/account-overview

## 4 · Analytics workload on Azure

Organiza la explicación:

**fuente → ingesta → procesamiento → almacén analítico → modelo → visualización**

### Azure Databricks
Pistas: Spark, notebooks, Databricks Runtime, ingeniería/ML, procesamiento distribuido.

### Microsoft Fabric
Pistas: plataforma SaaS analítica integrada, OneLake y cargas de trabajo conectadas.

### Batch vs streaming
- batch: lotes e intervalos;
- streaming: eventos conforme llegan / baja latencia.

El blueprint pide identificar servicios Microsoft para analítica en tiempo real. En S16 prioriza el patrón antes del catálogo.

### Power BI
- capacidades;
- modelos semánticos;
- informes;
- selección de visualización.

Ejemplos:
- tendencia temporal → línea;
- comparar categorías → barras;
- una métrica → card/KPI.

## Cómo resolver una pregunta DP-900

1. **¿Qué dominio es?**
2. **¿Qué condición manda?**
3. **¿Qué opciones resuelven otro patrón y puedo descartar?**
4. **¿Qué concepto del diplomado ya conozco?**
5. **¿Qué servicio Azure satisface la condición más específica?**
6. **Si fallé, fue concepto o nomenclatura Azure?**

## Practice Assessment

Haz **seis preguntas oficiales** en vivo.

Para cada una:
1. clasifica el dominio;
2. subraya la palabra/condición decisiva;
3. descarta distractores;
4. elige;
5. lee la explicación oficial;
6. identifica si el error fue conceptual o de nomenclatura.

No persigas cantidad. Seis preguntas bien razonadas enseñan más que veinte respuestas rápidas.
