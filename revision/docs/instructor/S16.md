# S16 · Guía docente · cierre fuerte del diplomado

## Propósito
La última sesión no es otra evaluación. Su objetivo es que el estudiante **vea, ordene y nombre el progreso acumulado** desde la primera consulta hasta una decisión completa de arquitectura de datos, y que después entienda qué parte de ese razonamiento se transfiere a DP-900.

La idea de cierre es:

> Empezaste consultando una tabla; terminaste pudiendo razonar grano, relaciones, integridad, almacenamiento y analítica.

## Principios de diseño
1. **No proyectar quejas, comentarios de encuestas ni decisiones internas de diseño curricular.** Úsalos para preparar la clase, no como contenido para el estudiante.
2. **No repetir las cinco preguntas abiertas de S1.** Ya existe el formulario institucional/curso y S15 ofrece evidencia más rica.
3. **No hacer un segundo examen custom después de S15.** El banco de 24 preguntas deja de formar parte de la clase.
4. **DP-900 es un puente, no el nuevo centro de S16.** Primero se consolida el diplomado; después se identifican nombres Azure nuevos.
5. **No pedir portafolios ni enlaces que el docente no planea revisar.** La evidencia del curso se muestra, no se recolecta.
6. **No enviar diagnóstico docente desde la presentación.** La última sesión no necesita otra capa de telemetría para cerrar bien.
7. **Una idea cognitiva por diapositiva.** En móvil, evita formularios largos y páginas que requieran scroll para comprender una sola idea.
8. **La encuesta institucional ocurre después del cierre**, sin pedir una mini encuesta adicional.

## Presupuesto docente · 180 minutos totales = 165 útiles + 15 de pausa
- **0–10 · Apertura + recorrido:** muestra la cadena completa del curso y la progresión S2→S15.
- **10–40 · SQL + pensamiento SQL:** sintaxis acumulada, orden de escritura, orden lógico, JOIN, grano y validación.
- **40–65 · De reglas a diseño:** entidades, cardinalidad, normalización, DDL/DML e integridad.
- **65–85 · Elegir almacenamiento + analítica:** SQL/NoSQL, documentos, CAP, OLTP/OLAP, warehouse.
- **85–100 · BigQuery + anidados + S15:** partición, clustering, pruning, formatos y transferencia.
- **100–115 · Pausa:** 15 minutos.
- **115–140 · Tres casos finales:** discusión sin nota sobre grano, patrón de acceso y separación OLTP/OLAP.
- **140–155 · Curso → DP-900:** qué ya está cubierto conceptualmente y qué nomenclatura Azure sí es nueva.
- **155–170 · Practice Assessment oficial:** 5 preguntas juntas; razonar concepto → reconocer servicio → leer explicación.
- **170–180 · Cheat Sheet + voucher + cierre:** entrega la referencia final, recuerda recursos oficiales y cierra con evidencia de capacidad.

No muestres minutaje por diapositiva; solo la pausa se proyecta.

## Qué debe verse en el cierre SQL
No reduzcas “SQL” a SELECT/WHERE/GROUP BY. Haz visibles tres niveles:

### A. Lenguaje
- SELECT, DISTINCT, alias.
- WHERE, AND/OR, BETWEEN, IN, LIKE, IS NULL.
- ORDER BY, LIMIT.
- COUNT, SUM, AVG, MIN, MAX.
- GROUP BY y HAVING.
- INNER/LEFT/RIGHT/FULL JOIN.
- UNION y UNION ALL.
- WITH / CTE.
- CASE y COALESCE.
- COUNT(DISTINCT).
- INSERT, UPDATE y DELETE.
- CREATE/ALTER/DROP TABLE.

### B. Orden mental
- Orden de escritura: SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT.
- Orden lógico: FROM → WHERE → GROUP BY → agregación → HAVING → SELECT → ORDER BY → LIMIT.
- WHERE filtra filas; HAVING filtra grupos.
- El resultado de un JOIN puede cambiar el grano.
- Comparar conteos antes y después de unir.
- Validar nulos, duplicados y cardinalidad.
- Último evento ≠ cualquier fila con ese estado.

### C. Pensamiento SQL
**pregunta → grano → tablas → llaves → unión → filtros → agregación → validación**

El aprendizaje importante para un grupo que partió con poca programación es saber descomponer el problema, no escribir código largo de memoria.

## Tres casos finales
No se califican ni se guardan.

1. **Reporte inflado por JOIN 1:N.** La respuesta esperada empieza por el grano y la multiplicación de filas.
2. **Pedido que siempre se consume completo.** La respuesta esperada razona patrón de acceso y embeber/referenciar antes de decir “documento”.
3. **Tablero histórico sobre transacciones operativas.** La respuesta esperada separa OLTP y analítica/warehouse.

Secuencia: decisión individual → conversación por parejas → resolución del docente.

## Practice Assessment
Haz **5 preguntas oficiales** en vivo. Para cada una:
1. tapa mentalmente los nombres Azure y pregunta cuál es el concepto;
2. identifica la condición que cambia la decisión;
3. elige el servicio;
4. lee la explicación oficial;
5. si el error fue solo nomenclatura, dilo: no lo conviertas en “no aprendiste bases de datos”.

Si sobra tiempo, continúa hasta 10.
