Datos imperfectos antes de modelar

La misma idea del Workbench: distinguir un hallazgo visible en los datos de una explicación sobre su causa.

diagnóstico

Ejemplo

SELECT caso_id, COUNT(*) AS filas
FROM casos_dirty
GROUP BY caso_id
HAVING COUNT(*) > 1;

Esta consulta demuestra duplicados; no explica por qué ocurrieron.

Hallazgo vs hipótesis

Solicita las pistas una a una. La respuesta se habilita después de la tercera.
Pista 1: “existe un evento cuyo caso no aparece” se puede verificar mirando las tablas.
Pista 2: “ocurrió por una falla de sincronización” intenta explicar la causa.
Pista 3: una causa no observada directamente debe tratarse como hipótesis, aunque parezca plausible.

Q1 · Alta por barrio

Devuelve SOLO barrios que tengan al menos un caso de prioridad Alta.

Contrato: Columnas exactas: barrio, casos_alta. No incluyas barrios con 0 casos Alta.
Ejemplo mínimo: Norte tiene 2 casos Alta y 1 Media. La respuesta para Norte debe ser 2; la fila Media no entra.
Solicita las pistas una a una. La respuesta se habilita después de la tercera.
Qué mirar: antes de contar, define la población. La palabra que manda es Alta.
Contraejemplo: si dejas prioridad='Media', responderás una pregunta distinta aunque el SQL ejecute sin error.
Orden: selecciona barrio y conteo → filtra Alta → agrupa por barrio.
SELECT barrio,
       COUNT(*) AS casos_alta
FROM casos_src
WHERE prioridad = 'Alta'
GROUP BY barrio;

Por qué: WHERE decide qué filas entran; GROUP BY barrio forma los grupos y COUNT(*) cuenta dentro de cada grupo.

Q2 · Último evento temporal

Compara el snapshot actual con el estado del evento de fecha más reciente de cada caso.

Contrato: Columnas exactas: caso_id, estado_actual, ultimo_estado. El orden lo define fecha_evento; no evento_id ni el orden alfabético del estado.
Ejemplo mínimo: caso 1001: 08:00 Cerrado, 10:00 Abierto. El último estado es Abierto, porque 10:00 es la fecha mayor.
Solicita las pistas una a una. La respuesta se habilita después de la tercera.
Qué mirar: MAX(estado) compara texto; no sabe cuál fila ocurrió de última.
Primer paso: calcula MAX(fecha_evento) por caso_id.
Segundo paso: vuelve a EVENTOS usando caso + fecha máxima para recuperar el estado de esa fila.
WITH ultima_fecha AS (
  SELECT caso_id,
         MAX(fecha_evento) AS fecha_evento
  FROM eventos_src
  GROUP BY caso_id
)
SELECT c.caso_id,
       c.estado AS estado_actual,
       e.estado AS ultimo_estado
FROM casos_src c
LEFT JOIN ultima_fecha u
  ON u.caso_id = c.caso_id
LEFT JOIN eventos_src e
  ON e.caso_id = u.caso_id
 AND e.fecha_evento = u.fecha_evento;

Por qué: primero respondes cuándo ocurrió el último evento; luego recuperas qué estado tenía esa fila.

Q3 · Minutos de casos terminados cerrados

Suma toda la trayectoria de los casos cuyo ÚLTIMO evento temporal es Cerrado.

Contrato: Columnas exactas: caso_id, minutos_hasta_cierre. Un caso reabierto no pertenece al conjunto aunque tenga un evento Cerrado antiguo.
Orden correcto: 1001 termina Cerrado: 0 + 90 + 40 = 130. 1002 tuvo un Cerrado antiguo pero termina Reabierto: no entra.
1 · último evento→2 · elegir casos→3 · volver al historial→4 · sumar
Solicita las pistas una a una. La respuesta se habilita después de la tercera.
Reutiliza Q2: todavía no sumes. Primero identifica el último evento temporal de cada caso.
Decide el conjunto: conserva únicamente los caso_id cuyo último estado es Cerrado.
Ahora sí suma: vuelve a eventos_src con esos IDs y suma todo el historial. WHERE estado='Cerrado' solo sumaría la fila Cerrado.
WITH ultima_fecha AS (
  SELECT caso_id,
         MAX(fecha_evento) AS fecha_evento
  FROM eventos_src
  GROUP BY caso_id
),
cerrados AS (
  SELECT u.caso_id
  FROM ultima_fecha u
  JOIN eventos_src e
    ON e.caso_id = u.caso_id
   AND e.fecha_evento = u.fecha_evento
  WHERE e.estado = 'Cerrado'
)
SELECT e.caso_id,
       SUM(e.minutos_desde_anterior) AS minutos_hasta_cierre
FROM eventos_src e
JOIN cerrados c
  ON c.caso_id = e.caso_id
GROUP BY e.caso_id;

Lectura: CTE 1 encuentra la última fecha; CTE 2 decide qué casos entran; la consulta final vuelve a todo el historial de esos casos y suma sus minutos.

Q4 · Grano tras JOIN

Entrega total_casos, total_eventos y casos_alta sin inflar casos por la relación 1:N.

Contrato: Una sola fila con columnas exactas: total_casos, total_eventos, casos_alta.
Ejemplo mínimo: si el caso 1001 tiene E1, E2 y E3, el JOIN produce 3 filas, pero siguen existiendo 1 caso y 3 eventos.
Solicita las pistas una a una. La respuesta se habilita después de la tercera.
Qué cambia: después de un JOIN 1:N, COUNT(*) cuenta filas del resultado.
Protege la entidad: para casos, cuenta DISTINCT c.caso_id; para eventos, cuenta e.evento_id.
Casos Alta: aplica la condición Alta al identificador del caso y protégelo también con DISTINCT.
SELECT COUNT(DISTINCT c.caso_id) AS total_casos,
       COUNT(e.evento_id) AS total_eventos,
       COUNT(DISTINCT CASE
         WHEN c.prioridad = 'Alta' THEN c.caso_id
       END) AS casos_alta
FROM casos_src c
LEFT JOIN eventos_src e
  ON e.caso_id = c.caso_id;

Por qué: el JOIN repite al caso por cada evento. DISTINCT evita convertir esas repeticiones en casos nuevos.

Qué estás aprendiendo

Q5 · Promedio por caso

Por tipo: cantidad de casos y promedio de minutos acumulados POR CASO; casos sin eventos valen 0.

Contrato: Columnas exactas: tipo, casos, promedio_minutos. Redondea promedio_minutos a 1 decimal.
Ejemplo mínimo: Caso A totaliza 10 min y Caso B 30 min. El promedio por caso es (10 + 30) / 2 = 20. Promediar directamente filas de evento respondería otra cosa.
Solicita las pistas una a una. La respuesta se habilita después de la tercera.
Grano: la pregunta dice “por caso”. Primero necesitas una fila por caso.
Primer nivel: suma minutos_desde_anterior agrupando por caso_id, tipo; un caso sin eventos debe quedar en 0.
Segundo nivel: ya con total_minutos por caso, agrupa por tipo y calcula AVG(total_minutos).
WITH por_caso AS (
  SELECT c.caso_id,
         c.tipo,
         COALESCE(SUM(e.minutos_desde_anterior), 0) AS total_minutos
  FROM casos_src c
  LEFT JOIN eventos_src e
    ON e.caso_id = c.caso_id
  GROUP BY c.caso_id, c.tipo
)
SELECT tipo,
       COUNT(*) AS casos,
       ROUND(AVG(total_minutos), 1) AS promedio_minutos
FROM por_caso
GROUP BY tipo;

Por qué: el CTE devuelve una fila por caso. Solo después se calcula el promedio entre casos.

Pruebas ya escritas

-- PK: un ID repetido debe fallar
INSERT INTO caso(caso_id,fecha_creacion,tipo,prioridad,estado,barrio)
VALUES (9001,'2026-09-02','Ruido','Alta','Abierto','Prueba');

-- FK: un caso inexistente debe fallar
INSERT INTO evento(evento_id,caso_id,fecha_evento,estado,minutos_desde_anterior)
VALUES (9200,9999,'2026-09-01 09:00','Abierto',0);

-- CHECK: 0 debe pasar; -1 debe fallar
INSERT INTO evento VALUES (9201,9001,'2026-09-01 10:00','Abierto',0);
INSERT INTO evento VALUES (9202,9001,'2026-09-01 10:10','Abierto',-1);

-- Evolución de dominio: ya preparado
INSERT INTO estado_catalogo(estado) VALUES ('Escalado');
Solicita las pistas una a una. La respuesta se habilita después de la tercera.
Pista 1: los identificadores que no pueden repetirse necesitan PRIMARY KEY; los datos obligatorios necesitan NOT NULL.
Pista 2: EVENTO pertenece a CASO: protege evento.caso_id con una FOREIGN KEY.
Pista 3: minutos puede ser 0, pero no negativo: la condición correcta usa >= 0.
CREATE TABLE caso(
  caso_id INTEGER PRIMARY KEY,
  fecha_creacion TEXT NOT NULL,
  tipo TEXT NOT NULL,
  prioridad TEXT NOT NULL,
  estado TEXT NOT NULL,
  barrio TEXT NOT NULL
);

CREATE TABLE evento(
  evento_id TEXT PRIMARY KEY,
  caso_id INTEGER NOT NULL,
  fecha_evento TEXT NOT NULL,
  estado TEXT NOT NULL,
  minutos_desde_anterior INTEGER NOT NULL
    CHECK (minutos_desde_anterior >= 0),
  FOREIGN KEY (caso_id) REFERENCES caso(caso_id)
);

Lectura: PK evita duplicados; FK evita eventos sin caso; NOT NULL protege datos obligatorios; CHECK acepta 0 y rechaza negativos.
